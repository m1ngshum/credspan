# Qualified generator dependency patch

As checked against the official npm registry on 2026-11-12, latest `@hey-api/openapi-ts` 0.99.0 uses latest `@hey-api/json-schema-ref-parser` 1.4.4, whose upstream package exactly pins `js-yaml` 4.2.0. That parser imports `load(data)` without custom YAML options. Three high CPU-exhaustion advisories affect this version:

| Advisory | Fixed 4.x version |
| --- | --- |
| [GHSA-52cp-r559-cp3m](https://github.com/advisories/GHSA-52cp-r559-cp3m) | 4.3.0 |
| [GHSA-5p4m-2wfm-xmqj](https://github.com/advisories/GHSA-5p4m-2wfm-xmqj) | 4.3.1 |
| [GHSA-2883-xcg3-v3hh](https://github.com/advisories/GHSA-2883-xcg3-v3hh) | 4.3.2 |

`pnpm-workspace.yaml` substitutes **only** `@hey-api/json-schema-ref-parser@1.4.4>js-yaml` with exact **4.3.2**. This keeps the existing 4.x `load` API while adding upstream work budgets. It does not replace all YAML packages, move the parser to 5.x, or suppress advisories. Swagger's separate js-yaml 5.5.0 is unchanged. Direct package versions and the lockfile remain pinned. The generator is a development dependency, not browser/API runtime logic.

## Qualification performed

The exact public parser/generator release tags both resolve to source commit `c9dc0b94b0bfd53b8614e31f450607e1db4d3c05` in [hey-api/hey-api](https://github.com/hey-api/hey-api/tree/c9dc0b94b0bfd53b8614e31f450607e1db4d3c05). In an isolated temporary sparse checkout of `packages/json-schema-ref-parser` and `specs`, all **20 upstream tests in three files passed** using the source's pinned Vitest 4.1.8, Node 26.13.1 and the patched installed parser-child dependencies. No upstream test/snapshot or fixture was edited. This includes real reference/bundle/YAML fixtures; the npm tarball alone omits the monorepo specs directory and is insufficient to reproduce the full suite.

Repository checks add JSON parsing/internal-reference preservation, valid YAML anchors/merge values, ordered maps, malformed/duplicate rejection and bounded empty-source merge work using the actually resolved parser's YAML version. `pnpm --filter @credspan/sdk check` asserts that resolved child version is 4.3.2 and runs those regressions. They do not claim to reproduce every advisory payload.

Actual SDK generation was compared with the same controller-produced JSON input and identical generator/configuration: js-yaml 4.2.0 versus patched 4.3.2. Recursive file paths and SHA-256 contents of **all** generated artifacts were identical, including generic client templates. The qualification baseline was deliberately rerun with a temporary Node resolution hook selecting the installed old 4.2.0 parser child; it was not a timestamp claim that newly recorded hashes predated the patch. The additional `pnpm check:generated` takes complete before/after path/content snapshots, detects additions/deletions, and checks current generation byte for byte independently of Git tracked status.

TypeScript 6.0.3 builds, actual generated SDK/API checks, the browser/independent-wallet journey and fresh audit qualify the installed graph. Fresh audit reports one remaining high legacy decoder advisory, zero moderate/critical; see [compatibility risks](compatibility.md). This is not a clean audit.

## Reproduction and retirement

Run frozen install, `pnpm --filter @credspan/sdk check`, `pnpm check:generated`, `pnpm check`, `pnpm test:browser` and `pnpm audit`. For the full upstream suite, fetch the exact release tag `@hey-api/json-schema-ref-parser@1.4.4` with the monorepo `specs`, resolve its package dependencies to this workspace's patched parser dependencies, and use Vitest 4.1.8 with globals enabled and the parser package as root; run `src/__tests__/*.test.ts` without snapshot updates. The local qualification retained source, test configuration/logs and generation manifests outside the repository for review; no credentials or upstream publication were involved.

Remove the override when an upstream parser release depends on a patched compatible YAML version. Reverify its actual dependency resolution, rerun parser/reference fixtures, complete generation snapshots, TypeScript/browser/client tests and audit before retiring or expanding this exception. Local generation still explicitly parses the fixed JSON input and rejects external references; a `.json` filename by itself is insufficient because the upstream parser can fall back to YAML after JSON parse failure. Do not accept untrusted YAML/remote specs or expose generation as a service.

## Version-bound legacy decoder backports (2026-11-13)

The latest Credo 0.7.4/PEX 6.1.1 graph still installs deprecated `@sd-jwt/decode` 0.7.2 and 0.9.2. There is no patched compatible decoder release to select. Two `pnpm.patchedDependencies` entries apply reviewed source patches to **only these exact versions**, to both CJS and ESM entrypoints. They preserve legacy exports, asynchronous/synchronous hashing and `Disclosure` objects (`_digest`, `encode()`), rather than aliasing them to the incompatible modern core package. Frozen installs and the image builder copy the patch files before dependency installation.

The initiating upstream security correction is [sd-jwt-js commit 3d8a72a0a279d67439db038c9c2b52621568b866](https://github.com/openwallet-foundation/sd-jwt-js/commit/3d8a72a0a279d67439db038c9c2b52621568b866). The traversal/duplicate/collision implementation is adapted from the already installed Apache-2.0 `@sd-jwt/core` **0.21.1** published artifact (npm integrity `sha512-lQfUOWTQGrHPVreWvs9ZhLznQqARK+VlkB64eqqKUL9QPJ2v5sEX/LN9yr61mfkDsYCU5veCUxCLd0GT6hGk6g==`). The registry supplies no gitHead for that release; this is artifact provenance, not an invented source commit match. Existing upstream licenses remain included in the packages.

The adaptation adds fatal UTF-8/canonical base64url JSON checks before legacy decoding, validates two- and three-item disclosure structures/reserved keys, rejects duplicate supplied disclosures before map collapse, and rejects unreferenced/reused payload digests, conflicting claims, malformed placeholders and object/array disclosure confusion. Raw path-segment semantics remain unchanged for legacy PEX compatibility, including literal `.` and `~` claim names; cross-nested duplicate accounting is retained. Root traversal validates serialized disclosure maps too: PEX directly calls `unpackObj`, bypassing `decodeSdJwt`. The supported hash profile is explicitly SHA-256/384/512; unsupported algorithms fail closed. This does not introduce broader PEX product support: the application's final/DCQL route exclusions and sentinels remain required.

`node --test scripts/check-decoder-patches.test.mjs` tests both patched versions in both module formats, synchronous/asynchronous decoding, valid nested object/array disclosure and selective omission controls, malformed encoding/UTF-8, reserved names, duplicates, conflicts and unreferenced disclosures. It also invokes the actual installed Sphereon decoder and PEX disclosure-selection callers to qualify their legacy object contract. Decoder tests use synthetic unsigned inputs and do not themselves establish signature verification. The separate real HTTP integration suite includes issuer signatures, fresh holder signatures with recomputed `sd_hash`, valid wallet issuance/presentation and rejection controls.

The raw audit continues to identify the original deprecated package versions/advisory; patching source does not change their published version metadata. Retain raw findings and distinguish qualified corrected behavior from a clean dependency audit or complete upstream-package replacement. Remove these patches only after a compatible maintained upstream graph eliminates the legacy decoder, with caller/API, signed-negative, wallet, build and raw audit requalification.

## Source-resolved wallet runtime refresh (2026-11-16)

The digest-pinned wallet 1.2.1 image contains an older runtime dependency graph than its exact public source revision. Compiling only the two modified libraries does not refresh those packaged dependencies. Both wallet builders therefore apply `vendor/waltid/dependencies.patch` and package the service's complete Gradle `installDist` library set, replacing the previous visible `/app` payload and runtime classpath, preserving the generated launcher's explicit service-first jar order. Original base bytes remain in inherited OCI layers; this is a final-filesystem refresh, not erasure of the base image archive. Default image SBOM/scans describe the visible final filesystem, not all inherited layer contents. The original entrypoint, working directory, persistence configuration and hosted bootstrap remain in use. Both builds pass the upstream release workflow's `-Pversion=1.2.1` property so service metadata and jar versions retain the tagged release instead of the checkout's default `1.0.0-SNAPSHOT`. Upstream license/notices and dependency jar notices remain included; the upstream notice inventory describes its original build, while each candidate SBOM records the actual refreshed artifacts.

The patch selects aligned [Netty 4.2.19](https://netty.io/news/2026/10/06/4-2-19-Final.html) and [Jackson 2.22.4](https://github.com/FasterXML/jackson/wiki/Jackson-Release-2.22.4) families already used by the source catalog, plus [Guava 33.8.0-jre](https://github.com/google/guava/releases/tag/v33.8.0) and [PostgreSQL JDBC 42.7.14](https://jdbc.postgresql.org/changelogs/2026-10-07-42.7.14-release/). The patch also prioritizes the already configured Maven Central repository before the upstream releases/snapshots repositories, retaining those fallbacks for upstream-only artifacts and normal TLS validation. This avoids an upstream snapshot repository failure blocking artifacts published in Central. The service also selects [Vert.x 4.5.35](https://vertx.io/blog/eclipse-vert-x-4-5-35/) from the existing 4.5 series, [JSON 20260719](https://github.com/stleary/JSON-java/releases/tag/20260719), and the [Rhino 1.7.15.1 security maintenance release](https://github.com/mozilla/rhino/releases/tag/Rhino1_7_15_1_Release). The upstream auth module’s local resolution rules do not propagate to the service distribution; these service-level selections prevent its old transitive jars returning. Rhino stays on the legacy 1.7 embedding/module contract rather than adopting the later engine reorganization. Gradle resolves their real transitive dependencies; no jar filename substitution, scanner ignore or missing-version rewrite is used. Alignment replaces the image's mixed Netty 4.1/4.2 graph, so actual wallet transport and persistence requalification remain required. This does not qualify AWS, arbitrary DID/credential ecosystems or other unused wallet routes.

The OS refresh installs exact Ubuntu 26.04 security revisions for already included packages: `apt`/`libapt-pkg7.0` 3.2.1ubuntu0.1 ([APT advisory](https://ubuntu.com/security/CVE-2026-109518)); `libc6`, `libc-bin`, `libc-gconv-modules-extra` and `locales` 2.43-2ubuntu2.7 ([glibc advisory](https://ubuntu.com/security/CVE-2026-97399)); `libpcre2-8-0` 10.46-1ubuntu0.1 ([PCRE2 advisory](https://ubuntu.com/security/CVE-2026-103111)); and `perl-base` 5.40.1-7ubuntu0.4 ([Perl advisory](https://ubuntu.com/security/CVE-2026-82560)). These stay within the base distribution's supported package/ABI series. Ubuntu repository URLs are explicitly switched to HTTPS and retries are disabled during the affected package manager's update. It performs no blanket distribution upgrade and retains TLS/signature validation. Actual wallet startup, native crypto, transport and cloned-state persistence checks must pass on the updated filesystem. The unused, package-unowned `/usr/bin/pebble` binary is removed from the visible filesystem: neither the direct Java entrypoint, hosted bootstrap, nor the repository configuration invokes it. This removes its old Go runtime from the active filesystem without changing the JVM; inherited OCI layer bytes still remain.

The local peer retains the preauthorized-only patch; the hosted peer additionally retains the exact-origin Access patch and its JVM test. Both run the protocol JVM suite, wallet service tests and `installDist`; the builder cache includes the dependency patch and full runtime inventory, with every regular file content-hashed. Real qualification uses the rebuilt images, a stopped/cloned synthetic holder database, retained credential/key presentation, signed revocation controls and API/native transport boundaries. `PREVIOUS_WALLET_IMAGE=sha256:... WALLET_IMAGE=sha256:... pnpm test:integration` runs the old-to-candidate holder-state check; without the previous-image setting it checks candidate restart/clone persistence. Final dated image, SBOM and unfiltered scan identities and any residuals belong in the review evidence.

New local deployments, browser integration and MCP preflight require the current dependency-patch label as well as the preauthorization label, so a historical image under the same local tag is rejected. The MCP API source pin is recorded in `packages/mcp/runtime.json`; it refers to a clean source snapshot in this repository. Updating that pin requires its own API build and MCP qualification; wallet qualification alone does not qualify the API graph. Existing local deployment records retain their immutable image IDs; replacing their runtime requires a separately qualified migration.

## Compatible maintenance selection (2026-11-17)

Official npm metadata, upstream release notes and peer ranges were checked on this date. The API aligns `@nestjs/common`, `@nestjs/core` and `@nestjs/platform-express` at **12.5.0**, with Swagger **12.1.2**. [Nest 12.5.0](https://github.com/nestjs/nest/releases/tag/v12.5.0) includes HTTP adapter and middleware corrections; [Swagger 12.1.2](https://github.com/nestjs/swagger/releases/tag/12.1.2) corrects schema exploration. Qualify the actual contract and generated client rather than assuming patch/minor upgrades preserve their bytes. Nest 12.5.1 was published less than 24 hours before selection and is deferred under `minimumReleaseAge: 1440`; no exclusion weakens that gate.

Keep major-upgrade PRs blocked until peers and full generation/API/SDK checks pass; do not introduce a second compiler solely to upgrade. |

| Legacy decoder backports and parser-child YAML override | Exact versions and patch bytes remain unchanged. The caller, signed-negative, parser and complete generation checks above remain required. The raw legacy decoder advisory is retained; this is not a clean audit or new image scan. Remove only under the documented upstream replacement conditions. |

The modified wallet remains on [released 1.2.1](https://github.com/walt-id/waltid-identity/releases/tag/v1.2.1). Retire `preauthorized-only.patch` only when an unmodified release accepts valid preauthorized-only metadata and rejects the malformed/mixed cases in the real wallet flow. Retire `access.patch` only with an equivalent reviewed exact-origin, redirect and logging boundary (or a separately approved boundary change), including negative transport tests. Retire `dependencies.patch` only when the released distribution supplies a compatible corrected graph, verified by the actual runtime inventory, dated SBOM/scans and retained-key holder-state/crypto/transport checks. A newer tag or a green source build alone does not meet these conditions. This maintenance does not change the wallet patches, MCP API source pin, public API or storage schema.
