This is a dated **interim** 2026-11-12 Linux arm64 scan baseline, not a clean audit, trusted release or production approval. Final source/image/SBOM/scan/signature hashes belong in the PR evidence, outside source, to avoid a self-referential commit-hash loop. Re-scan the exact final image after code/base changes.

The initial Node 26.13.1 Bookworm slim image reported 1 critical and 42 high package findings. The candidate moved to official Node 26.13.1 **Trixie slim**, retained its immutable upstream index digest, removed unused runtime npm/npx and installed the exact Debian security package `zlib1g=1:1.3.dfsg+really1.3.1-1+deb13u1`. The builder retains its separate package tooling. No application dependency override was introduced for these image changes.

Syft 1.57.1 and Trivy 0.76.2 on that patched candidate report **0 critical, 48 high, 79 medium, 65 low and 14 unknown package instances**, using vulnerability DB updated 2026-11-12 07:01 UTC. Forty-six high instances map to eleven OS advisories; two are the already documented legacy decoder versions. Counts are package instances, not unique bugs. The unfiltered scan and SBOM are retained; nothing is ignored or marked fixed merely because Debian defers an update. A newer distro does not monotonically reduce every finding.

## Runtime replacement qualification (2026-11-13)

The follow-up runtime uses official glibc distroless `nodejs26-debian13:nonroot`, pinned by index digest in `ops/images.json` and the Dockerfile. The Node/pnpm builder remains unchanged. Executing that exact ARM64 runtime reports Node **26.13.1**, preserving the existing application version. Upstream keyless signature verification succeeds for issuer `https://accounts.google.com` and identity `keyless@distroless.iam.gserviceaccount.com`; verify that exact digest with pinned cosign before changing it. An image tag or configuration alone does not establish the bundled Node version.

The runtime explicitly clears the upstream entrypoint and adds `/nodejs/bin` to PATH, preserving existing exec-form `node` API, readiness and maintenance commands. It defaults to UID/GID 65532; managed Compose deliberately uses the invoking user's UID with private initialized volumes. No shell, package manager or inspection utilities are added. Test fixture UID/file/signal inspection uses Node APIs instead of `id`, `cat` and `touch`. The first candidate drill's missing-utility failures are retained outside source; the corrected fixture preserves native stale-write, recovery and rekey assertions.

Exact source-bound SBOMs, **unfiltered** before/after scans, image IDs, signature qualification and full native/API/operations outcomes belong in PR evidence. The earlier package-instance counts above remain historical baseline evidence, not the new runtime's results. A smaller image is not proof that every component is fixed or that the application is production-ready. The patched legacy decoder versions still appear in raw vulnerability metadata; see [version-bound patch provenance](dependency-patches.md). Required hosted checks and exact-base/head review remain merge gates. Public deployment requires separate authorization and qualification.

### Remaining stable-distribution findings

The first distroless candidate's unfiltered scan reports **0 critical, 2 high, 39 medium, 13 low and 7 unknown package instances**. Both highs identify the original legacy decoder versions/CVE-2026-62374; their source backport and caller/security qualification are documented separately. The Debian OS findings remain visible, with no fixed version reported by that scan. These counts are a dated candidate baseline; final source/image/report hashes and results remain in PR evidence.

As checked on 2026-11-13, the installed stable Trixie security packages OpenSSL `3.5.7-1~deb13u3`, glibc `2.41-12+deb13u4` and GCC `14.2.0-19` match Debian's current stable versions; no newer compatible stable remedy was identified. An empty scanner FixedVersion or a deferred Debian update does not establish safety. The [OpenSSL 2026-11-10 advisory](https://openssl-library.org/news/secadv/20261110.txt) rates five scanner-unknown issues low upstream, with fixes in GitHub but releases scheduled for December 1; the 3.5-series target 3.5.10 is not represented as available. Their conditions involve CMS encryption with an attacker-controlled EC order-one certificate, QUIC, or AES-GCM-SIV reset/IV handling. The backup uses `aes-256-gcm`, not GCM-SIV; this is a narrow operation distinction, not blanket OpenSSL unreachability proof. Node may also contain bundled cryptographic components, so system-package reasoning alone is insufficient.

The residual glibc issues include `regcomp`/`regexec` reallocation failure under memory pressure (CVE-2026-100290) and wide `scanf` string conversion into a narrow buffer (CVE-2026-115819). No fixed compatible stable package was identified. Retain these findings and recheck vendor updates; no unstable distribution, custom compiler/runtime fork, blanket suppression or clean-audit claim is introduced to improve scanner counts.
